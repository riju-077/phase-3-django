  Correction 1 — how DRF excluded author/views                                                                                                 
                                                                                                                                               
  I was wrong earlier when I said "DRF detected they have defaults." The real reason they're missing from the form is what you did — you added 
  read_only_fields = ['author', 'views'] to serializers.py. DRF reads that list and removes those fields from the form.                        
                                                                                                                                               
  auto_now / auto_now_add is the only thing DRF auto-detects (that's why created_at and updated_at were never in the form). For author and
  views, your read_only_fields line is doing the work.

  Correction 2 — there's no slug on Post

  I just checked your models.py — your Post model doesn't have a slug field at all. Only Category does. So my "POST will fail because slug is
  missing" warning yesterday was nonsense. Apologies for the false alarm.

  What the actual error is saying

  Read the error message in plain English:

  ▎ null value in column "author_id" of relation "posts_post" violates not-null constraint

  Translation: "PostgreSQL got asked to insert a row into posts_post with author_id = NULL, but the column is NOT NULL, so it refused."

  Why is author_id NULL? Because:
  - You marked author as read-only in the serializer → form doesn't ask for it, serializer ignores any incoming author value
  - Your PostViewSet doesn't set it either
  - So when DRF saves, the author field is empty → NULL hits the DB → boom

  This is exactly the situation read_only_fields creates: the client can't supply it, so the server has to. Right now your server isn't
  supplying it, so nobody is.

  The fix — one method on PostViewSet

  Open posts/api_views.py and add one method to PostViewSet:

  class PostViewSet(viewsets.ModelViewSet):
      queryset = Post.objects.filter(published=True)
      serializer_class = PostSerializer

      def perform_create(self, serializer):
          serializer.save(author=self.request.user)

  That's it — no slugify, no extra imports, just three lines.

  What it does:
  - DRF calls perform_create(self, serializer) right before the save happens on a POST
  - serializer.save(author=self.request.user) injects author = the logged-in user (you) before the row is inserted
  - All the other fields (title, body, category, etc.) are still pulled from the form as normal

  So now every new post gets stamped with whoever is logged in as the author — exactly what you want. No way for one user to claim to be
  another, because the client never gets a say.
