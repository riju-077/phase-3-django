 What a router is                                                                                                                             
                                                                                                                                             
  You've actually seen this trick before. Look at your blog/urls.py:                                                                           
                                                                                                                                               
  path('admin/', admin.site.urls),                                                                                                             
                                                                                                                                               
  One line. And yet /admin/ gives you hundreds of working URLs — one per model, one per action (add, edit, delete, history…). Django's admin
  generated all those URLs from your registered models. You didn't list them by hand.

  A router is the same idea for DRF.

  You register one ViewSet → router auto-generates the matching URL patterns:

  ┌──────────────┬─────────────┬───────────────────┐
  │     URL      │ HTTP method │ What it triggers  │
  ├──────────────┼─────────────┼───────────────────┤
  │ /posts/      │ GET         │ list all posts    │
  ├──────────────┼─────────────┼───────────────────┤
  │ /posts/      │ POST        │ create a new post │
  ├──────────────┼─────────────┼───────────────────┤
  │ /posts/<id>/ │ GET         │ one post          │
  ├──────────────┼─────────────┼───────────────────┤
  │ /posts/<id>/ │ PUT         │ update post       │
  ├──────────────┼─────────────┼───────────────────┤
  │ /posts/<id>/ │ PATCH       │ partial update    │
  ├──────────────┼─────────────┼───────────────────┤
  │ /posts/<id>/ │ DELETE      │ delete post       │
  └──────────────┴─────────────┴───────────────────┘

  You write one registration line. The router builds all six URL routes.

  Your turn — wire it up

  Open posts/api_urls.py and replace the whole file with this:

  from django.urls import path, include
  from rest_framework.routers import DefaultRouter
  from . import api_views

  router = DefaultRouter()
  router.register('posts', api_views.PostViewSet, basename='post')

  urlpatterns = [
      path('', include(router.urls)),
      path('stats/', api_views.StatsAPIView.as_view(), name='api-stats'),
      path('categories/', api_views.CategoryListAPIView.as_view(), name='api-category-list'),
  ]

  Three things to notice:

  1. The old posts/ and posts/<int:pk>/ path() lines are gone — the router builds those for you now. (If we left them in, Django would pick
  them first and your shiny new ViewSet would never run.)
  2. router.register('posts', PostViewSet, basename='post') — "URL prefix posts, run by PostViewSet, internal name stem post." Same idea as
  admin.site.register(Post) — register the thing, get the screens.
  3. path('', include(router.urls)) — paste all the router-generated URLs into the URL list. Stats and categories stay as plain path() because
  they're not full CRUD — just one GET each.

  Your analogy

  That's basically right. When you router.register('posts', PostViewSet), the 'posts' becomes a URL prefix — and underneath that prefix the
  router lays down 6 endpoints (list, create, detail, update, patch, delete). The "folder" framing captures the grouping correctly.

  One sharpening: the folder isn't just organising URLs you'd otherwise write — the router auto-creates the 6 endpoints from the ViewSet.
  That's the part that's different from regular path() calls. With a regular path(), you write each URL line yourself. With a router, you write
   one register line and 6 routes appear.

  So: prefix grouping = right, auto-generation = the bigger win. Both are happening.

  Why no form

  Look at your screenshot — you're seeing raw JSON only, no form at the bottom. That happens for one of these reasons:

  1. You're not logged in. Your REST_FRAMEWORK settings have IsAuthenticatedOrReadOnly — anonymous users can read but cannot create. DRF hides
  the create form when you don't have permission to use it. Most likely cause.
  2. The serializer has no writable fields — less likely, but worth a peek.
