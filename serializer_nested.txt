  Edit 2 — make PostSerializer use nested objects for author and category. Add two field declarations at the top of the class (before class

  class PostSerializer(serializers.ModelSerializer):
      author = AuthorSerializer(read_only=True)
      category = CategorySerializer(read_only=True)

      class Meta:
          ...

  read_only=True on these two means: "in responses, show the full nested object. On POST/PUT, ignore these fields."

  Edit 3 — but now you can't set the category on POST anymore (it's read-only). Fix by adding a separate write-only field that maps incoming
  category_id onto the model's category:

  class PostSerializer(serializers.ModelSerializer):
      author = AuthorSerializer(read_only=True)
      category = CategorySerializer(read_only=True)
      category_id = serializers.PrimaryKeyRelatedField(
          queryset=Category.objects.all(),
          source='category',
          write_only=True,
          required=False,
          allow_null=True,
      )

      class Meta:
          model = Post
          fields = [
              'id', 'title', 'body',
              'author', 'category', 'category_id',
              'created_at', 'updated_at',
              'published', 'views',
          ]
          read_only_fields = ['author', 'views']

  Decoding the new field:

  ┌─────────────────────────────────┬────────────────────────────────────────────────────────────────────────────┐
  │               Bit               │                                  Meaning                                   │
  ├─────────────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ PrimaryKeyRelatedField          │ Accepts a plain integer ID from the client                                 │
  ├─────────────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ queryset=Category.objects.all() │ Tells DRF which table to look the ID up in                                 │
  ├─────────────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ source='category'               │ "When this comes in, assign it to the model's category attribute"          │
  ├─────────────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ write_only=True                 │ Never appears in GET responses (the nested category already does that job) │
  ├─────────────────────────────────┼────────────────────────────────────────────────────────────────────────────┤
  │ required=False, allow_null=True │ Posts without a category are allowed (matches the model)                   │
  └─────────────────────────────────┴────────────────────────────────────────────────────────────────────────────┘

  This is the classic read/write split pattern in DRF. Output side: nested objects. Input side: bare IDs. Both live on the same serializer.
