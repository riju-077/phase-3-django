  └─────────────────────────────┴──────────────────────────────────────────────────┴───────────────────────────────────────────────────────┘

  IsAuthorOrReadOnly lives inside DRF's permission machinery. The admin doesn't import it, doesn't run it, doesn't know it exists. So:

  - akash (superuser) can still delete any post via /admin/. Superusers bypass everything.
  - aditya (regular user) can't reach /admin/ at all unless you set is_staff=True on him. Even then, he'd need explicit delete_post permission
  granted in the admin's permissions UI.

  This split is on purpose, and it's how production sites are built. The admin is for trusted operators (you, content moderators). The API is
  for end users. They have completely separate rules because they serve completely different audiences.
